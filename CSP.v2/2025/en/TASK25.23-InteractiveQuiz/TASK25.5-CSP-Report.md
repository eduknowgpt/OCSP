# Competency Specification Report: Task25.5 – Interactive Quiz on Hardware and Software Concepts

## Introduction

This report presents the application of the **Competency Specification Process (CSP)** to *Task25.5 – Interactive Quiz on Hardware and Software Concepts*.
The task engages students in a dynamic and participatory learning experience using the **Kahoot platform** to reinforce foundational concepts in **computer hardware, software, and basic computer architecture**.

By combining formative assessment, immediate feedback, and collaborative discussion, the activity promotes both **cognitive consolidation** and **social learning**, while strengthening the students’ ability to recognize, classify, and reason about core elements of computing systems.
In alignment with the BNCC and OntoKSD framework, this CSP-Report identifies the knowledge structures, competencies, and learning objectives mobilized through this interactive practice.



## 1. Instructional Entity Analysis

### Title

    Interactive Quiz – Foundations of Hardware and Software


### Description

Learners participate in a **15-question interactive quiz** covering fundamental concepts of **computer hardware, system software, application software, and basic computer architecture**.
Using the Kahoot platform, students answer questions in real time and receive immediate feedback. After each item, a guided class discussion consolidates the conceptual understanding and clarifies misconceptions.

The instructional entity focuses on:

* identifying components of a computer system;
* distinguishing hardware and software categories;
* understanding interactions between hardware, software, and performance;
* solving scenario-based questions involving system assembly and behavior.



### Solution Development Process

The expected learner approach involves:

* **Recognizing** and interpreting hardware components and software categories;
* **Analyzing** scenario-based problems to determine correct system behavior;
* **Selecting** correct answers under time constraints, reinforcing recall and decision-making;
* **Discussing** the reasoning behind responses during teacher-led feedback sessions;
* **Correcting** conceptual misunderstandings through collaborative explanation and debate;
* **Connecting** quiz content to prior theoretical lessons on computer architecture.



### Expected Outcomes

Learners should produce:

* Demonstrated understanding of hardware and software concepts through quiz performance;
* Accurate classification of system components and their respective roles;
* Clear verbal explanations of their reasoning during post-quiz discussions;
* Evidence of improved conceptual clarity after immediate feedback cycles;
* Engagement in collaborative correction and peer-supported learning.



### Acquisition Context

This task is implemented within the **Computer Architecture** unit of the **1st year Integrated Technical Program in Informatics** at IFBA.
It is part of a pedagogical sequence designed to:

* transition from theoretical study to applied review;
* strengthen retention through gamification;
* diagnose conceptual gaps prior to formal assessments.

The activity occurs in the **computer laboratory**, using students’ mobile devices or institutional computers with internet access.



### Target Audience Profile

* **Educational Level:** First-year students of the Integrated Technical Program in Informatics.
* **Prior Knowledge:** Introductory concepts in computer systems, hardware components, and basic digital terminology.
* **Technological Skills:** Comfortable using mobile devices or computers for instructional activities.
* **Learning Needs:** Visual reinforcement, immediate feedback, structured discussion of misconceptions, and motivational engagement.
* **Expected Dispositions:** Curiosity, receptiveness to feedback, respectful communication, and willingness to collaborate.



### Proficiency Scale

Scores range from **0.0 to 10.0**, in increments of **0.1**, based on the following criteria:

* Accuracy and speed in answering quiz questions;
* Ability to justify responses during follow-up discussions;
* Mastery of technical vocabulary and conceptual clarity;
* Active participation and respectful engagement;
* Demonstrated improvement across rounds of questioning.



## 2. Knowledge Enumeration

The task mobilizes the following areas of knowledge:

### 2.1. Computer Hardware Fundamentals

* K1 – Identification of hardware components (CPU, RAM, storage, I/O devices)
* K2 – Functions and roles of hardware units
* K3 – Relationship between hardware configuration and system performance

### 2.2. Software Concepts

* K4 – Distinction between system software and application software
* K5 – Understanding the operating system as a resource manager
* K6 – Software–hardware interaction (drivers, instructions, processes)

### 2.3. Computer Architecture Basics

* K7 – Von Neumann architecture principles
* K8 – Data flow between CPU, memory, and peripherals

### 2.4. Analytical and Diagnostic Reasoning

* K9 – Interpretation of scenario-based problems
* K10 – Recognition of faults, mismatches, or misconfigurations

### 2.5. Vocabulary and Communication

* K11 – Technical terminology related to hardware and software
* K12 – Explanation of reasoning during conceptual discussions

### 2.6. Collaborative Learning

* K13 – Peer discussion, justification of ideas, and negotiation of interpretations



## 3. Learning Objectives Identification

> By the end of the activity, learners should be able to:

1. **LO1 – Identify** key hardware components and describe their primary functions.
2. **LO2 – Distinguish** between system software and application software in real-world contexts.
3. **LO3 – Explain** how hardware and software interact within a computer system.
4. **LO4 – Analyze** scenario-based questions to determine correct system behavior or diagnosis.
5. **LO5 – Use** correct technical vocabulary to articulate conceptual understanding.
6. **LO6 – Justify** responses through oral explanation, demonstrating logical reasoning.
7. **LO7 – Reflect** on incorrect answers and revise conceptual understanding through immediate feedback.
8. **LO8 – Collaborate** with peers during discussions, contributing respectfully to collective learning.

## Competency CT25.5.1 Specification

### Competency Title

    Understand and apply hardware and software concepts in problem-solving scenarios

### Textual Description

This competency involves the ability to **recognize, relate, and apply** fundamental concepts of hardware and software in practical or simulated contexts.
Learners identify the **physical and logical components** of a computer system, analyze how the interaction between hardware and software affects performance, and apply these concepts to **interpret and solve scenario-based quiz questions**.
During the interactive activity, students justify their responses using principles of **computer architecture, resource management, and system behavior**.


### Knowledge Specification

* **Hardware and Software Concepts**

    * Learners **apply** foundational knowledge of physical components and software categories to answer questions requiring understanding of system functions and interdependence.

    * **Bloom Level:** Apply
    * **Verb Annotation:** Use, Employ
    * **KS Pairing:** Hardware–Software Concepts / Apply

* **Hardware–Software Interaction**

    * Learners **analyze** how hardware configuration, operating system behavior, and software use influence system performance.

    * **Bloom Level:** Analyze
    * **Verb Annotation:** Differentiate, Examine
    * **KS Pairing:** Hardware–Software Relationship / Analyze



### Disposition Specification

* **Meticulous** — Attends to technical details when interpreting scenarios and reviewing answers.
* **Critical** — Analyzes causes, consequences, and performance implications of hardware–software interaction.



### BNCC Alignment

* **General Computing Competency 1 (EM)** — Understanding the possibilities and limits of computing when solving problems.
* **EM13CO01** — Exploring and constructing solutions involving different levels of abstraction in computational systems.
* **EF07CO03** — Identifying physical and logical components of computational devices and their roles in program execution.
