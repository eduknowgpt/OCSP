
# Instructional Entity Analysis Report


## Purpose
Establish a solid foundation for competency authoring by thoroughly documenting the instructional entity's pedagogical and contextual elements (CSP Phase 1A).



## 1. Title

    [Insert concise, descriptive title]

Guidance: Should reflect the core problem or challenge in a few focused words).



## 2. Description

    [Summarize the central issue, scenario, or problem learners must address]

Guidance: Explain who, what, why—e.g., “Learners model a soda machine’s operation under varying coin inputs to validate automata behaviors.”



## 3. Solution Development Process

    [Outline expected steps/approach learners should follow]

Guidance: Provide a logical sequence such as:

- Analyze user interactions

- Design FSM states/transitions

- Test using sample inputs

- Implement hardware/software prototype



## 4. Expected Outcomes

    [List artifacts, behaviors, or deliverables indicating success]

Examples:

- FSM diagram with complete transitions

- Regex patterns for input validation

- Functional prototype with dispensing logic



## 5. Acquisition Context

    [Describe learning or application scenario]

Guidance: Describe the learning or application scenario in which this activity occurs. This should be general enough to support reuse across similar instructional entities.

    

## 6. Target Audience Profile

    [Define learner characteristics such as level of expertise or educational stage, affecting task design]

Include: Learning stage (academic level as 2nd or 3rd year), roles in task (writing code, debugging systems, designing algorithms, and modeling computational processes).



## 7. Proficiency Scale

    [Specify performance levels mapped to competency expectations]

Example Scale:

- Novice – Creates partial FSM diagrams with missing transitions

- Competent – Designs complete FSMs and validates via regex tests

- Advanced – Extends system to hardware prototype and edge-case scenarios
