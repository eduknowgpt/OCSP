# Instructional Entity Analysis Report

## Purpose

Establish the contextual and pedagogical basis for competency authoring by documenting the instructional entity analyzed in CSP Phase 1A.

Within this thesis, the completed report is used as an input to competency specification in Phase 1B and as requirement evidence for OntoKSD. It documents expected instructional conditions and does not constitute evidence of learner performance.

## 1. Title

    [Insert a concise, descriptive title.]

**Guidance:** The title should identify the central problem or challenge in a few focused words.

## 2. Description

    [Summarize the central issue, scenario, or problem that learners must address.]

**Guidance:** Explain who is involved, what must be addressed, and why the task is relevant. For example: “Learners model the operation of a vending machine under different coin inputs to validate automata behavior.”

## 3. Solution Development Process

    [Outline the steps or approach learners are expected to follow.]

**Guidance:** Describe the expected sequence at the level provided by the instructional entity. For example:

- Analyze user interactions.
- Design FSM states and transitions.
- Test the model using sample inputs.
- Implement the hardware or software prototype.

## 4. Expected Outcomes

    [List the artifacts, behaviors, or deliverables expected from successful task execution.]

**Examples:**

- FSM diagram with complete transitions.
- Regular expressions for input validation.
- Functional prototype with dispensing logic.

## 5. Acquisition Context

    [Describe the learning or application context in which the competencies are expected to be mobilized.]

**Guidance:** Describe the instructional or application setting relevant to the activity. State the context clearly enough to support interpretation and comparison across similar instructional entities.

## 6. Target Audience Profile

    [Describe the learner characteristics that affect the design or interpretation of the task, such as educational stage or level of experience.]

**Guidance:** When applicable, indicate the learners’ academic stage (for example, second or third year) and their expected roles in the task, such as writing code, debugging systems, designing algorithms, or modeling computational processes.

## 7. Proficiency Scale

    [Specify the performance levels used to characterize the expected proficiency, when applicable.]

**Example scale:**

- **Novice:** Limited or partial task execution; misses key components or handles only simple cases (grade range ≤ 5, when this grading scale applies).
- **Competent:** Fully addresses the core task requirements with accurate and complete performance in typical scenarios (grade range > 5 and ≤ 9, when this grading scale applies).
- **Advanced:** Meets all task requirements and also addresses enhancements, edge cases, or well-justified design decisions (grade range > 9, when this grading scale applies).

**Guidance:** Use the proficiency scale adopted in the instructional context. If no scale is defined or required, record this explicitly. The scale expresses assumptions used for competency specification and does not report attained learner proficiency.
